## Лаборатори №1-ээс өөрчлөгдсөн нь

Хүн P-г удирдахын оронд A агент замаа төлөвлөж өөрөө хөдөлнө.
Нэг алхмын Smart Hint-ийг олон алхмын хайлтаар сольсон.
OOP бүтэц: `State`, `Environment`, `Rule`, `KnowledgeBase`,
`SearchResult`, `IntelligentAgent`. Агент KB-тай, орчин State-тай гэсэн
composition холбоо ашигласан. Lab1-ийн Object-оос удамших нь энэ хувилбарт
шаардлагатай биш тул тусдаа Object класс ашиглаагүй.

Үндсэн урсгал:

1. `Environment.percept()` — харагдах талбай, төлөв, сүүлчийн ажиглалтыг өгөх.
2. `update_knowledge()` — шинэ факт нэмэх, хүчингүй болсон фактыг хасах.
3. `infer()` — шинэ факт гарахаа болих хүртэл дүрэм давтан хэрэглэх.
4. `choose_goal()` — түлхүүргүй бол Key, түлхүүртэй бол Exit.
5. `search()` — BFS эсвэл A* ашиглан зорилт хүрэх бүтэн зам олох.
6. `program()` — төлөвлөгөөний эхний үйлдлийг сонгох.
7. `execute_action()` — хөдөлж, оноо/объект/төлөв шинэчлэх.
8. Дараагийн percept-ээс дахин төлөвлөх.

## State-space search problem

`State` нь өөрчлөгддөггүй (`frozen=True`) dataclass:

| Талбар | Утга |
|---|---|
| position | Агентын (мөр, багана), индекс 0-ээс эхэлнэ |
| has_key | Түлхүүртэй эсэх |
| score | Тоглоомын оноо |
| collected_coins | Авсан зоосны координатын frozenset |
| visited_cells | Очсон нүднүүд, эхлэх нүдийг оруулна |
| consumed | Нэг удаа авсан C/B/K объектын координат |

Initial state: seed-ээр сонгосон байрлал, түлхүүргүй, 100 оноо.
Actions: UP, DOWN, LEFT, RIGHT. Transition: хууль ёсны хөдөлгөөнөөр
`transition()` шинэ State буцаана. Goal: эхний үе шатанд K, эцэст нь
түлхүүртэйгээр E. Хил, хана, түгжээтэй хаалга руу successor үүсгэхгүй.
Хавханд дахин орвол дахин торгуультай; зоос/бонусыг давтан авахгүй.

### Closed/best түлхүүр яагаад бүтэн State биш вэ?

Хайлтын node бүр бүтэн State хадгална. Харин давталт хянах `best` dictionary
нь `(position, has_key)` түлхүүртэй. Энэ загварт оноо, зоос, өмнөх айлчлал нь
замын өртөг, хууль ёсны дараагийн үйлдэл, goal test-д нөлөөлөхгүй.
Тиймээс ижил байрлал/түлхүүртэй өндөр өртөгтэй замыг хасаж болно.
Энэ нь state abstraction буюу хэрэгтэй хэсгээр нь ялгах арга.

Хэрэв "3 зоостой гарах", "оноо 0 бол үхэх", "очсон нүдэнд дахин орж болохгүй"
зэрэг дүрэм нэмбэл энэ хураангуйлал буруу болно. Тэр үед best түлхүүрт
тухайн нэмэлт төлөвийг оруулах шаардлагатай.

## BFS ба A*

BFS: FIFO `deque`, `popleft()`, түвшин дараалал. Хамгийн цөөн алхамтай
замыг олно. Хавхны нэмэлт өртгийг сонголтдоо ашиглахгүй, гэхдээ олсон замын
жинлэсэн өртгийг тооцож тайланд гаргана.

A*: `heapq` priority queue. `f(n)=g(n)+h(n)`.
`g(n)` нь алхам ба эрсдэлийн хуримтлагдсан өртөг.
`h(n)=abs(r-r_goal)+abs(c-c_goal)` буюу Manhattan зай.
Хамгийн бага нэг алхмын өртөг 1, диагональ хөдөлгөөнгүй тул энэ heuristic
мэдэгдэж буй газрын зураг дээр хэтрүүлж үнэлэхгүй, consistent байна.
Ижил priority үед serial counter-аар тогтвортой дараалал сонгоно.

| Нүд | Замын өртөг | Тоглоомын онооны өөрчлөлт, хөдөлгөөнийг оруулсан |
|---|---:|---:|
| Хоосон / K / E | 1 | -1 |
| C | 1 | +9, зөвхөн анх авахад |
| B | 1 | +4..+19, зөвхөн анх авахад |
| T | 8 | -16 |
| ? | Төлөвлөхөд 1 | Илэрсэн төрлөөс хамаарна |

Хавхны cost=8: нэг хөдөлгөөн + эрсдэлийн 7 нэгжийн торгууль.
Замын cost ба тоглоомын score нь өөр хэмжигдэхүүн. Зоос, бонусын шагналаар
хайлтын cost-ийг хасахгүй; сөрөг ирмэг үүсгэхгүй. Агент нийт оноог дээдлэх
зорилготой биш, түлхүүр/гарцад алхам эсвэл эрсдэлийн бага өртгөөр хүрнэ.

Хоёр үе шатыг тус тус оновчилно; бүх боломжит зоос/бонус цуглуулах эсвэл
нууц мэдээлэлтэй орчны бүх тоглолтыг глобал оновчтой болгох баталгаа биш.

## Knowledge Base ба forward chaining

Fact жишээ: `('Trap', (2, 4))`, `('HasKey', False)`.

| Rule | Premise | Conclusion |
|---|---|---|
| R1 | HasKey=False | Goal=Key |
| R2 | HasKey=True | Goal=Exit |
| R3 | Wall(p) | NotTraversable(p) |
| R4 | Trap(p) | Dangerous(p) |
| R5 | Dangerous(p) | Avoid(p) |
| R6 | Coin(p) | PositiveUtility(p) |
| R7 | Bonus(p) | PositiveUtility(p) |

`Rule.apply()` баримтыг шалгаад шинэ факт буцаана. `infer()` бүх дүрмийг
одоогийн фактуудад хэрэглэж, additions set-д шинэ баримт цуглуулна.
Дараа нь тэдгээрийг facts-д нэмээд давтана. Нэмэлт факт гарахаа болих үед
зогсоно. Ингэснээр Trap -> Dangerous нь нэг давталтад, Dangerous -> Avoid
нь дараагийн давталтад гарна. Нэг шатны if/else-ийг inference гэж нэрлээгүй.

Дүгнэлт хайлттай бодитоор холбогдоно:
- Goal факт зорилтыг сонгоно.
- NotTraversable факт successor-ийг хориглоно.
- Avoid факт A*-ийн ирмэгийн cost-ийг 8 болгоно.
- PositiveUtility нь тайлбарлах нэмэлт мэдлэг; энэ хувилбарт замын cost-д
  нөлөөлөхгүй, учир нь зорилго нь хамгийн их шагнал цуглуулах биш.

Percept бүрд одоогийн үндсэн фактуудыг дахин бүрдүүлж, derived facts-ийг
дахин гаргана. Ингэснээр Key авсны дараа хуучин Goal=Key, HasKey=False
үлдэхгүй. RETRACTED FACTS-д өмнөх дүгнэлтүүд ч орж болно: энэ нь refresh
аргын онцлог бөгөөд ижил дүгнэлт шинэ infer()-ээр дахин гарч болно.

## Үл мэдэгдэх объект

Бүх газрын зураг харагдана, зөвхөн ?-ийн төрөл нууц. Нууц төрөл ба бонусын
бодит хэмжээг зөвхөн Environment хадгална. Planner тэдгээрийг хүлээн авахгүй.
? руу ороход бодит төрөл илэрч, дараагийн percept ба KB шинэчлэгдэнэ.
Нууц хавх бол Unknown -> Trap -> Dangerous -> Avoid болно.
Зоос/бонус бол тэр дороо авагдах тул газрын зурагт Empty болж,
ObservedCoin/ObservedBonus факт болон логт тухайн ажиглалт үлдэнэ.
Бонусын хэмжээг planner-д хамгийн бага 5 гэж тооцсон боловч route choice
нь score-оос хамаарахгүй. Бодит бонусыг execute_action тооцно.

Мэдэгдээгүй ?-ийг 1 өртөгтэй гэж таамагладаг. Хэрэв хавх байвал орсны дараа
бодит cost=8 болно. Агент дараагийн алхамд шинэ мэдлэгээр дахин төлөвлөнө.
A* нь хараахан мэдээгүй хавхыг урьдчилан тойрох баталгаагүй.

## Шударга харьцуулалт ба хэмжүүр

Нэг seed-ээр нэг base орчин үүсгээд `deepcopy`-гоор хоёр тусдаа хуулбар
гаргана. Талбай, эхлэх байрлал, нууц объект, координат бүрийн бонус адил.
Нэг алгоритмын авсан зоос нөгөө алгоритмын талбайгаас арилахгүй.

- path_length: бодитоор хийсэн нийт хөдөлгөөн.
- expanded_nodes: бүх дахин төлөвлөлтийн successor гаргасан node-ийн нийлбэр;
  goal node-ийг өргөжүүлсэнд тооцохгүй. Давтан төлөвлөх тул өвөрмөц нүдний
  тоотой адил биш, мөн нэг удаагийн хайлтын expanded-тэй шууд харьцуулахгүй.
- total_path_cost: бодит алхмын cost-ийн нийлбэр, нууц хавхыг оруулна.
- search_seconds: зөвхөн хайлт хийсэн нийт хугацаа.
- execution_seconds: агентын нийт гүйлтийн хугацаа, reasoning/log текст
  бэлтгэхийг оруулна; файл бичих, орчин үүсгэхийг оруулахгүй.
- goal_reached: түлхүүртэйгээр E-д хүрсэн эсэх.

`--explain` нь хэвлэх хугацаа нэмж execution_seconds-д нөлөөлнө.
Хугацаа төхөөрөмж, ачааллаас хамаарна; давтан гүйлтэд өөр байна.
Санамсаргүй нэг seed дээр хоёр алгоритм ижил зам сонгох нь хэвийн.

6×6, seed=129 жишээ гүйлт: BFS 8 алхам, 56 expanded, cost 8;
A* 8 алхам, 22 expanded, cost 8. Хоёул гарсан, score=92.
Энэ нь багц бэлтгэсэн орчны гүйлт; чиний Debian дээрх хэмжилт биш.

## Шалгалт ба хамгаалалт
